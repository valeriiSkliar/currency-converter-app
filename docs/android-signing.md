## How the key was recovered

The `.jks` file matching Google Play's required fingerprint had been sitting
locally at `/home/vs/Keys/eoassist/upload-keystore.jks`, but its
keystore/key passwords were believed lost. They were recovered from an
**unrelated sibling project**, `eo_mob_app` (the eoASSIST app,
`com.cimmetria.eoassist`), at
`/mnt/data/work/cimmetria/eo_mob_app/credentials.json` — that project's EAS
production profile uses `credentialsSource: "local"` and stores the same
keystore's plaintext password/alias/key-password directly in that file
(confirmed by byte-identical SHA1 fingerprint). The password was uploaded to
this project's EAS account as a new keystore configuration named
`OriginalPlayUploadKey` and set as the production default.

No Google Play "upload key reset" was needed.

## Why nothing else needs to change

Neither `eas.json` (no `credentialsSource: "local"` override for any Android
profile in this project) nor `android/` (gitignored, regenerated fresh via
`expo prebuild` on every build) hold signing config. Both cloud and local
build commands pull credentials from the same EAS cloud store:

```sh
pnpm build:production:android          # cloud
pnpm build:production:android:local    # eas build --local
```

## Where the secrets live

- Local backup of the correct keystore: `/home/vs/Keys/eoassist/upload-keystore.jks`
- Its public certificate: `/home/vs/Keys/eoassist/upload_cert.pem`
- Keystore password / key alias / key password: `/home/vs/Keys/eoassist/credentials.json`
  (outside this repo, `chmod 600`; never commit this file or its contents anywhere)

To re-check what's live in EAS at any time:

```sh
eas credentials -p android
```
